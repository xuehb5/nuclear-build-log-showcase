# 核电工程新闻自动采集与 AI 协同工作流详解

**[简体中文](ai-workflow.md) · [English](ai-workflow.en.md) · [返回产品介绍](../README.md)**

核程志将“读懂信息”与“可靠执行”分开：大模型辅助语义判断和内容编辑，程序负责采集、证据校验、可追溯存储与视图联动，用户决定新闻确认和报告采用。本文描述2026年10月29日核对的现有功能，不公开内部提示词、接口凭据或核心实现。

## 一、从新闻到可核对的台账

1. 定时或手动采集国内核电工程新闻；用户也可导入普通网页、公众号链接，或补充经过验证的原文正文。公众号需要访问验证时单独保留待验证记录，不伪装成已经读到正文的新闻。
2. 程序读取并清洗正文，去除可辨认的广告和页面导航，提取发布时间、正文日期、候选机组及工程主题。发布时间与工程发生日分别存储；没有明确工程日期时不补造。
3. 程序先处理链接与内容重复。首次装料等唯一节点与设备到货等重复性事件分别判断；后者须比较设备、模块或工作对象。对规则无法确定的少量边界候选，配置的 AI 可辅助判断，结果仍须通过程序约束。
4. 新闻进入台账，按发布月份组织，用户可查看原文、摘要和日期并手动编辑。新闻卡片摘要仍使用现有程序生成逻辑，不能把“有 AI 辅助”宣传为所有摘要都由 API 生成。

## 二、从确认新闻到项目、进度和地图

后台可以提前进行 AI 复核，缓存语义结果；用户点击确认时复用匹配的缓存，必要时进行复核。AI 关注的是：文章主旨到底报道了什么、实际发生还是计划、哪些机组直接参与、日期属于哪个事件、是否构成可更新的节点，以及是否提到数据库没有的新项目。

程序校验证据是否来自原文、日期是否有依据、机组是否符合证据、结果是否满足采用条件。有效且高置信的模型判断可修正规则；模型不可用、证据无效或把握不足时由规则兜底。最终给用户一个明确的更新或未更新结果，不要求用户进入额外的 AI 待审核队列。

对于已有机组，程序按实际节点更新项目台账，保留可追溯的新闻影响。对于新机组，结合来源支持的资料执行新增；全新厂址还需地理资料识别与必要核验。不能把同一厂址其他机组的背景事件当成本机组事件，也不能把普通模块吊装直接当成核岛穹顶吊装。

项目台账是后续视图的数据来源：

- **项目状态**呈现阶段、堆型、所属公司、地区和工程节点。
- **进度可视化**读取台账日期和状态，按统一历时公式计算 ACT；规划/待开工机组不入图，已商运不显示 ECT。
- **核电地图**读取厂址位置与机组阶段，支持省份、厂址和项目之间的选择与定位。AI 辅助的是上游信息理解，坐标定位和地图绘制由程序执行。
- 用户手动新增和编辑也会影响相同视图；新闻产生的自动更新有相应提示，人工操作不冒充 AI 自动发现。
- 将已确认新闻恢复为未确认，会撤销该新闻对应的自动影响；仍须遵守系统对其他新闻证据和人工修改的保护逻辑。

### 流程中的工程术语

| 术语 | 工作台中的含义 |
| --- | --- |
| FCD | 用于计算建设历时起点的首次混凝土浇筑日期 |
| COD | 商业运行日期；已商运机组按此日期结束历时统计 |
| ACT | 实际历时（月），按总天数除以30.4375计算；在建统计至当前日期，已商运统计至 COD |
| ECT | 用于比较的预计总工期（月）；仅在符合条件的机组中显示 |
| 里程碑 | 带有工程意义的事件及其日期；有事件不代表一定改变整体工程阶段 |
| NI / CI | 工程报告中的核岛 / 常规岛与 BOP 表述 |

## 三、监管文件识别、分类与留存

监管归档是一条独立流程，常规三天检查一次，范围从2025年1月1日起，扫描国家核安全局和生态环境部的相关官方栏目、分页与文件页。

程序先确认日期及候选内容。配置 AI 后，模型帮助辨别对象是否是核电厂或机组主体，文件是否为环境影响报告书、建造或运行许可证，并从包含多个项目的公示与附件中选择相关资料。独立配套设施和环境影响报告表不在当前范围内。

模型不能创造下载链接或凭空认定文件存在。程序核对原文和附件证据，下载实际官方附件，验证格式和哈希，保存网页快照与附件版本，并按类型归档。相同附件可被多个公示关联，不因删除一个公示而破坏仍被其他公示引用的文件。失败保留记录并可补查，已有存档不会因官网链接失效自动删除。

这里的资料“归纳”是有范围约束的识别、分类和整理；当前不将它描述为已经具备政策法律分析或自动生成政策摘要的系统。

## 四、从选稿到工程编辑版成品

用户从新闻台账批量选稿或导入链接，组成独立报告。程序提供原文证据、工程日期、机组资料、FCD 月数和可用图片。本地翻译可作为粗稿；配置 API 后，大模型校译并进行工程编辑，突出工程主旨，压缩无关党建、会议或宣传内容，而不是只替换几个术语。

大模型依照报告要求生成标题、摘要、正文、关键词、语义高亮、图注和配图布局建议；程序负责固定字体、标题底纹、摘要框等文档样式与格式校验，并提供必要的内容兜底。用户可以编辑事实、工程日期、文字和图片，再导出单篇或整期工程编辑版/完整译文。

导出按工程时间排列，无具体日期的文章置于文末；多篇文章之间分页。报告内的事实编辑和内容生成不改变新闻确认状态，也不直接更新机组项目状态。

真实输出见[进度图](../assets/progress-chart.png)与[陆丰1号机组工程编辑版 PDF](../examples/lufeng-1-editorial-example.pdf)。样例使用既有生成内容重新导出，没有为展示重新编写正文。

## 五、可控性与适用边界

AI 调用取决于是否配置并启用可用 API，不等同于每次按钮点击都会请求模型。后台预处理、内容缓存和候选筛选用于减少重复调用；接口故障或没有 API 时保留规则路径。程序规则与 AI 共同降低错误，但不承诺全网无遗漏或所有新闻语义零误判。

用户仍应核对原始来源。原网站访问验证、网络故障、历史附件删除，以及报道本身缺少日期或明确机组，都是实际边界。平台保留来源和证据，帮助发现和纠正问题，而不把模型判断当成官方事实。
